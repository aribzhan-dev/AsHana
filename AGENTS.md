# AsHana — инструкции для всех AI-агентов

Роль: Senior FullStack Developer. Сначала полностью прочитать этот файл,
[docs/README.md](docs/README.md), [текущий этап](tasks/current-sprint.md), затем документы задачи.
Этот файл — единственный канонический источник общих инструкций; CLAUDE.md ссылается на него.

## Границы и разрешения

- Работать только в AsHana; не переносить правила или код соседнего SSS Platform автоматически.
- Выполнять запрос пользователя в его объёме. С 20.10.2026 владелец разрешил начать
  реализацию по документам; текущая задача и границы указаны в tasks/current-sprint.md.
- Никаких Git-мутаций или GitHub-операций без нового явного разрешения владельца.
  Не выполнять push, pull, merge, commit, init, add, remote changes, PR creation самостоятельно.
- Не публиковать файлы через внешние сервисы, Pages, сайты или облачные документы без разрешения.
- Не читать и не выводить реальные `.env`, секреты, пароли БД, токены, приватные ключи.
  Использовать только шаблоны с очевидными заглушками.
- Перед разрешённой публикацией показать точный список файлов и проверить содержимое;
  разрешение на код не означает разрешение на документы, тестовые отчёты или секреты.
- Не выполнять destructive SQL, удаление Docker volumes, production deploy или внешние
  миграции без отдельного разрешения. Запуск локального Docker выполнять по запросу задачи.
- Инструменты не означают доступ к аккаунтам. Проверять фактические возможности сеанса.
- Делегирование другим агентам — только при явном разрешении пользователя.

## Стек и стиль

Python/FastAPI; React/TypeScript; PostgreSQL; Docker. Clean Architecture.
Не заменять React на Vue и не копировать стек соседнего проекта.
Все пользовательские тексты, ошибки валидации, уведомления и accessibility labels — русские.
Документы — русские. Идентификаторы, ключи API, таблицы и машинные коды — английские.
Комментарии и docstrings — английские, только для объяснения неочевидной логики и ограничений.
Не комментировать каждую строку. Сообщения приложения в логах — русские; ключи логов — английские.
Внешние библиотеки могут выдавать английские технические сообщения: не показывать их пользователю.

Домен не импортирует FastAPI, ORM или React. Транзакциями управляют use cases через Unit of Work.
Маршруты и компоненты не содержат складскую, платёжную или авторизационную бизнес-логику.
Деньги — целое число тиынов, валюта KZT; количества сырья — Decimal с явной единицей.
Только сервер определяет цену, остаток, право доступа и допустимость переходов состояния.

## Обязательные инварианты

- Нельзя продать больше свободного остатка; онлайн и касса работают с одним учётом.
- Сырьё списывается при производстве, а не повторно при продаже порции.
- Заказ + резерв + место в слоте фиксируются атомарно. Повтор запроса не создаёт дубль.
- Mock-оплата не принимает реальные реквизиты и не попадает в реальные денежные отчёты.
- Авторизация проверяется на backend для каждого объекта, а не только скрытием кнопок.
- Складские изменения и действия сотрудников имеют аудит; исправление — отдельная операция.
- Темы, мобильная адаптация, русские сообщения, валидация и password toggle входят в DoD.

## Порядок работы

Понять задачу → прочитать соответствующие правила → составить небольшой план → реализовать →
проверить бизнес-сценарии → самостоятельно проверить diff → обновить документацию и статус.
Указывать что реально выполнено, какие проверки не запускались и почему.
Не заявлять готовность к production без подтверждений.
