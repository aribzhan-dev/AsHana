# Результат PRODUCTION-01

Дата: 21.10.2026. По запросу владельца реализован [PRODUCTION-01](PRODUCTION-01.md).
Ранее завершены FOUNDATION-01, IDENTITY-01, UI-01 и INVENTORY-01.
Сотрудники входят по логину/паролю администратора; телефон — необязательный KZ-контакт.
Публичной регистрации нет. Заказы, меню, касса и оплата пока не реализованы.

## Реализовано

- [x] Неизменяемые версии рецептов: нормы сырья, плановый выход, масса/объём готовой порции,
  технология, автор и время. Конкурентное изменение защищено previous_version и блокировкой.
- [x] Фактический расход по нескольким партиям одного ингредиента; все ингредиенты рецепта
  обязательны, лишние/дубли партий отклоняются. Фактический выход отличается от планового.
- [x] Атомарные расход сырья + движения + готовая партия + запись выпуска + аудит + idempotency.
  У всех исходных партий стабильный порядок row locks; сроки проверяются после получения блокировок.
- [x] Только пригодное свободное сырьё; нельзя затронуть резерв, просроченное/приостановленное
  сырьё или уйти в минус. Сотрудник явно подтверждает пригодность; срок готового продукта вводит сам.
- [x] production.manage для всех production API, включая справочник, историю и replay.
  Кухня работает без inventory.manage; смена ролей не позволяет обойти серверную проверку.
- [x] PostgreSQL migration 0005_production, CHECK/FK/unique и запрет runtime UPDATE/DELETE
  четырёх production-таблиц. Ранее применённые миграции не изменены.
- [x] `/staff/production`: версии/формы/история, рецепт конкретного выпуска, пагинация,
  подтверждение, loading/error/empty, сохранение ключа повтора, обе темы и мобильные размеры.
- [x] Общий useOperation для inventory/production; native select с длинным названием
  не расширяет мобильную форму. OpenAPI snapshot и TypeScript-типы обновлены.
- [x] Для собственной продукции склад явно показывает, что себестоимость ещё не рассчитана.
- [x] Самостоятельный review и [ADR-0010](../docs/architecture/decisions/0010-production-transactions.md),
  [инструкция](../docs/engineering/production-usage.md), актуальные документы.

## Фактические проверки

- **Backend: 80 passed**, включая **17 PostgreSQL integration**. Локально: 63 passed, 17 skipped.
- Production: immutable-версия старого выпуска, отдельные партии повторных приготовлений,
  расход из нескольких поставок с точной конверсией до 6 знаков; фактический выход независимо от нормы.
- PostgreSQL-гонки: одинаковый ключ создаёт один выпуск; разные ключи на последнее сырьё
  дают один успех; производство против складского списания не превышает остаток; две новые
  версии с одним previous_version дают один успех. Ключи разных сотрудников имеют отдельный scope.
- Недостача последнего заблокированного ингредиента, истечение, приостановка, резерв,
  пропущенный/дублированный ингредиент и сбой аудита не оставляют частичного выпуска.
  Повтор после сбоя проходит ровно один раз. Проверены immutable permissions и CHECK выхода.
- HTTP: гость, CSRF, no-store, ошибочные числа, кухня без складских прав, replay после
  отзыва роли в новой сессии. Сохранены identity/inventory проверки предыдущих этапов.
- **Vitest: 29 passed**. Нормы старой версии редактируются в g/ml без потери точности;
  неверный контракт отклоняется; подтверждение пригодности обязательно; фактический расход
  и введённые данные сохраняются при потере ответа, повтор использует прежний ключ.
- **Playwright/Chromium: 23 passed**. Новая версия рецепта → фактический выпуск → история →
  точная версия рецепта выпуска. Гость не получает рецепты, повар не получает inventory API.
  Рецепты/история/форма проверены на 360/390/768/1280/1440 в light/dark без overflow;
  сохранены полные сценарии identity и склада.
- Ruff check/format, mypy strict, ESLint, Prettier, TypeScript/Vite build — успешно.
- OpenAPI соответствует коду; Markdown-ссылки и границы domain/application проверены.
- Изолированный Docker: upgrade 0001→0002→0003→0004→0005, повторный upgrade, сохранение
  прежнего identity, runtime privileges, отказ/восстановление DB/API и точная readiness-ревизия.
- Визуально просмотрены форма выпуска 390, история 390 light и рецепты 1280 dark.
  Снимки — `frontend/test-results/production-*/`, только синтетические данные.
  Auth traces/video выключены; временный тестовый пароль не публикуется в выводе/текстовых артефактах.

Финальный полный прогон: **ashana-check-21c4d9**, backend и 23 E2E успешны.
Промежуточные проверки выявили перенос внутри SQL-литерала новой миграции, отозванную сессию
в тестовой фикстуре после смены роли и overflow native select с длинными именами. Всё исправлено
и проверено повторно. Защита сессий/лимиты приложения не ослаблялись. Общая тестовая admin-сессия
уменьшила лишние входы, а cook.ui имеет отдельный аккаунт только в тестовой базе.
Тестовые контейнеры удалены, volumes сохранены. Есть прежнее предупреждение Starlette
о deprecated httpx-адаптере TestClient; тесты проходят.

Полный WCAG-аудит, другие браузеры/физические устройства, нагрузка и процент coverage
не выполнялись. Продажи/заказы и проверка отсутствия повторного сырьевого расхода именно
при продаже ещё не проверены: соответствующих модулей нет. Production readiness не заявляется.

## Следующий этап и ограничения

**CATALOG-01:** меню/периоды и публикация доступных готовых партий. Затем ORDERS-01.
Стоимость собственного выпуска не рассчитывается автоматически; технический ноль не является
финансовой себестоимостью. Исходный выпуск/расход неизменяемы; исправления — отдельные
складские пересчёты/списания с причиной, без автоматического возврата приготовленного сырья.
Reserved ещё не создаётся приложением; ограничения проверены тестовой фикстурой.
Разбор испорченных зарезервированных партий и уведомления потребуются на этапе заказов;
сейчас затрагивающее резерв изменение отклоняется. WIP, архивирование рецептов и
редактирование справочника не входят в этот этап.
