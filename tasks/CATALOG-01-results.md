# Текущий этап: CATALOG-01 выполнен

Дата: 21.10.2026. По запросу владельца реализован [CATALOG-01](CATALOG-01.md).
Ранее завершены FOUNDATION-01, IDENTITY-01, UI-01, INVENTORY-01 и PRODUCTION-01.
[Сохранённый результат производства](PRODUCTION-01-results.md).

## Реализовано

- [x] Периоды с названием, интервалом до суток, датой начала по Алматы и публикацией.
  Часы завтрака/обеда задаёт управляющий; начало включительно, окончание исключительно.
- [x] Позиции собственной продукции/покупных товаров: описание, порция/упаковка, цена KZT
  в целых тиынах, независимая публикация. Сырьё не доступно для выбора.
- [x] Версии + row locks защищают от устаревших форм; запись, before/after audit и replay
  атомарны. Повтор неизменённого запроса не создаёт дубль.
- [x] catalog.manage на всех управляющих API и replay, CSRF на запись, shared identity lock.
  Admin без manager управляет сотрудниками; меню доступно manager.
- [x] Публичное меню `/` без регистрации: только опубликованные активные позиции с пригодным
  свободным готовым остатком. Reserved, истёкшие, приостановленные и ещё не полученные партии
  исключены. Агрегация/фильтрация до пагинации в одном SQL statement; склад не меняется.
- [x] DTO без авторов, себестоимости, внутренних item/batch IDs и личных данных; no-store.
  Обновление каждые 30 секунд, при focus и вручную; ошибка скрывает прежние данные.
- [x] `/staff/catalog`: создание/редактирование/снятие публикации, формы, пагинация,
  loading/error/empty, обе темы и мобильная адаптация. Staff-страницы загружаются отдельно.
- [x] Миграция 0006_catalog, runtime-запрет DELETE карточек/периодов и UPDATE/DELETE аудита;
  прежние миграции не изменены. OpenAPI и TypeScript-контракт актуальны.
- [x] Самостоятельный review по ashana-review, [ADR-0011](../docs/architecture/decisions/0011-catalog-publication.md),
  [контракт модуля](../docs/modules/catalog.md), [инструкция](../docs/engineering/catalog-usage.md).

## Фактические проверки

- **Backend: 91 passed**, включая **22 PostgreSQL integration**. Локально: 69 passed, 22 skipped.
- Каталог: точные границы периода/дата Алматы, предельная календарная дата, нулевая цена,
  строгие boolean/integer; черновики/будущие/завершённые периоды скрыты.
- Сумма пригодных партий исключает резерв, expiry, suspend, списанное и полностью занятое;
  реальное производство добавляет блюдо в меню; сырьё и товар без готового остатка не появляются.
- PostgreSQL: конкурентный replay создаёт одну запись; две правки одной версии — один успех;
  before/after audit; ошибка аудита откатывает карточку и ключ; unique/CHECK/immutable audit.
- HTTP: публичный минимальный DTO/no-store, guest 401 для управления, CSRF 403, strict 422,
  отзыв роли запрещает replay и в новой сессии. Сохранены проверки identity/inventory/production.
- **Vitest: 36 passed**. Алматы→UTC и версия формы, неверный интервал, точные тиыны,
  повтор с прежним ключом после потери ответа, испорченный контракт, удаление старого меню
  при ошибке обновления, loading/error/retry и предыдущие UI-сценарии.
- **Playwright/Chromium: 24 passed**. Manager создаёт черновик периода и опубликованную позицию;
  отдельный гостевой context не видит её до публикации периода, затем видит 8 шт/цену/упаковку;
  изменение цены и снятие публикации отражаются у гостя. Управление для гостя закрыто.
- Меню/периоды/форма периода проверены на 360/390/768/1280/1440 в light/dark без overflow.
  Форма позиции проверена на 390; визуально просмотрены её снимок, меню 390 light и 1280 dark.
  Сохранены полные сценарии входа/управления сотрудниками, склада и производства.
- Ruff check/format, mypy strict, ESLint, Prettier, TypeScript/Vite build — успешно.
  OpenAPI соответствует приложению; Markdown-ссылки и domain/application boundaries проверены.
- Полный изолированный Docker-прогон **ashana-check-6deeed**: upgrade 0001→…→0006,
  повторный upgrade, прежний identity сохранён, runtime permissions, отказ/восстановление DB/API.
  Тестовые контейнеры удалены, volumes сохранены.

Первый browser-прогон выявил дублирующий status при загрузке меню — исправлено и проверено
