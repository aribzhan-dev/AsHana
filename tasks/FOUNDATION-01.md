# FOUNDATION-01 — основа приложения

Статус: выполнено 20.10.2026, по запросу владельца начать реализацию.
Объём: backend, frontend, локальный Docker, конфигурация, lockfiles и проверки основы.
Бизнес-модули, авторизация, реальные данные и внешние интеграции в этот этап не входят.

## Требования и приёмка

- R16: FastAPI composition root; инфраструктурные проверки не содержат бизнес-логики.
  Приложение не подключается к БД и не выполняет миграции при импорте.
- R17: db → отдельный migrate → api → web запускаются в Docker.
  Liveness не зависит от БД; readiness проверяет соединение и текущую миграцию.
  Повторный upgrade безопасен; runtime-роль не имеет DDL-прав.
- R11: стартовый экран, состояния загрузки/ошибки и API-ошибки на русском;
  ошибки имеют code, message, field_errors, request_id без внутренних исключений.
- R12: light/dark/system, сохранение выбора и применение до первого отображения.
- R13: проверка ширин 360, 390, 768, 1280, 1440 без горизонтального переполнения.
- R18: только локальная работа, без Git-мутаций, публикаций и чтения реальных `.env`.
- Зависимости закреплены uv/pnpm lockfiles; проходят lint, format, typecheck,
  backend/frontend тесты, сборка и smoke-проверка в браузере.

R14/R15 будут проверяться при появлении пользовательских форм в IDENTITY-01.
Здесь нет полей пароля и нет имитации готового меню/заказов.

## План

1. Создать конфигурацию, FastAPI health/error contract и Alembic baseline.
2. Создать React-экран и общий HTTP-клиент с типами из OpenAPI, темы и адаптивность.
3. Связать PostgreSQL, мигратор, API и web в локальном Docker.
4. Проверить успех и отказ зависимостей, ограничения runtime-роли, UI и обновить статус.

Риски: доступность package registries/Docker images; права локального Docker;
повторный запуск на существующем volume. Локальные данные не удалять.
Baseline не создаёт бизнес-таблиц и не заполняет demo-данные.

## Результат

Созданы `backend`, `frontend`, `infrastructure/docker`, `compose.yaml`, `.env.example`,
скрипты экспорта контракта и изолированной проверки. Решения — ADR-0006.
Проверки: 8 backend + 6 frontend + 13 Chromium E2E; lint, format, typecheck и build.
Docker-проверка подтверждает порядок запуска, повторяемость миграций, разделение ролей
и восстановление после отказа БД/API. Все критерии выше выполнены в объёме основы.
При самопроверке исправлены конфликт одинакового image tag при параллельной сборке,
запуск init-script через host mount и ранний healthcheck временного PostgreSQL.
Мобильные действия проверены после обычной вертикальной прокрутки; переполнения по ширине нет.
Git diff недоступен: Git не инициализирован; новые исходники и изменения документов
просмотрены напрямую без Git-операций.
Полные результаты и ограничения — [текущий этап](current-sprint.md).
