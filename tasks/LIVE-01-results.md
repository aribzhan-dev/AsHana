# Текущий этап: LIVE-01 выполнен

22.10.2026. [Задача](LIVE-01.md), [ADR-0020](../docs/architecture/decisions/0020-live-staff-screens.md),
[предыдущий OPERATIONS-02](OPERATIONS-02-results.md). Миграция `0014_realtime`.

## Реализовано

- Триггеры PostgreSQL (`order_events`, `pos_attempts`, `inventory_movements`, `catalog_entries`)
  отправляют `pg_notify` только после commit. API слушает канал и раздаёт сигналы через
  WebSocket `/api/v1/staff/events`: сессия сотрудника, проверка Origin, фильтр тем по правам,
  перепроверка сессии раз в минуту. В сообщении нет кода получения, телефона и сумм.
- Кухня: индикатор связи, плашка «Новый заказ №…», включаемый звук, список и сводка
  обновляются сразу. Касса: наличие обновляется после онлайн-заказов, продаж и движений склада.
- Без связи — переподключение (до 30 секунд) и опрос каждые 15 секунд; при связи —
  страховочный опрос раз в 60 секунд. nginx и Vite проксируют WebSocket.
- Новая зависимость: `websockets` 15.0.1 (сервер WebSocket для uvicorn).

## Проверки

- **144 backend** на изолированном стенде: разбор событий и фильтр прав, переполнение очереди
  (resync), WebSocket с настоящим PostgreSQL — 4401 без сессии, 4403 для чужого Origin,
  событие оплаченного заказа без кода получения, сигнал склада для кладовщика.
- **63 Vitest**: перезагрузка по сигналу с объединением пачки событий, плашка нового заказа,
  переподключение и опрос без связи. Найдена и исправлена ошибка: смена статуса связи
  отменяла уже запланированную перезагрузку.
- **33 Chromium E2E**, включая новый: кухня видит оплаченный заказ в течение 5 секунд без
  обновления страницы (опрос при связи — 60 секунд, значит работает живой канал).
- Ruff, mypy `src` чисто; mypy тестов — 57 прежних ошибок. ESLint, Prettier, TypeScript, build.
- Стенд 8080 через nginx: «Обновляется сразу», тестовый заказ появился за ~1 секунду.
