# UI-01 — общие компоненты, формы и мобильная компоновка

Статус: выполнено и проверено. 20.10.2026. Требования R11–R16/R18.
Уточнение владельца: сотрудники входят по логину и паролю, которые выдаёт администратор.
Телефон — контактная информация, не идентификатор входа. Публичной регистрации нет.
В поле телефона нужен placeholder; громоздкий выбор темы заменить компактным управлением с иконками.

## План и приёмка

1. Отдельный уникальный login в domain/use cases/API/БД; поиск сотрудника по login.
   Нормализация регистра, 3–40 ASCII-символов (первая буква, далее буквы/цифры/._-).
   Телефон необязателен; при заполнении только KZ MOBILE. Совпадение телефонов допустимо.
   Новая миграция сохраняет UUID, хэши паролей, роли, контакты и сессии существующих сотрудников.
   Для старых записей login = staff_ + UUID без дефисов; bootstrap запрашивает login.
2. Общие Button/IconButton, Input/PasswordInput/PhoneInput/QuantityInput/Select,
   CheckboxGroup, Card/Badge, Loading/Empty/Error, Dialog/Toast и оболочка страницы.
   Использовать их в текущих формах; числовой компонент подготовить для будущих модулей.
   ProductCard/OrderStatus реализуются с их предметными данными в CATALOG/ORDERS.
3. Разделить вход, управление сотрудниками и сессии на компоненты. Placeholder не заменяет
   постоянную подпись. Ошибки поля связаны aria-describedby; серверные ошибки сохраняются.
   Отправка блокирует повторное действие; успех виден рядом с формой и объявляется assistive tech.
4. Иконки солнца/луны/системы, доступные названия и выбор light/dark/system. Клавиатура,
   Escape и возврат фокуса для диалогов. Password toggle с eye-иконкой, paste/IME работают.
5. Ширины 360/390/768/1280/1440, touch targets >=44px, отсутствие горизонтального overflow,
   обе темы и сохранение предпочтения. Сессии адаптируются в карточки на мобильном.
6. Проверки: unit/UI, PostgreSQL (включая upgrade с существующей записью), браузер,
   lint/typecheck/build; самопроверка и обновление документов. Git/публикации запрещены.

Риски: потеря доступа при смене идентификатора, несовпадение UI/API, фокус модальных окон,
утечки credentials. Секреты не выводить; локальные volumes не удалять.

## Результат

Все шесть пунктов приёмки выполнены в указанном объёме. Проверки: 48 backend, 19 Vitest,
19 Playwright/Chromium; линтеры, типизация и build успешны. Migration preservation проверен
на реальном PostgreSQL. Визуально просмотрены обе темы и мобильный кабинет.
Полные доказательства, ограничения и запуск admin — в [текущем этапе](current-sprint.md).
