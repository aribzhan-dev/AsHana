# Работа с рецептами и производством

Раздел `/staff/production` доступен повару и управляющему после входа по логину/паролю.
Администратор выдаёт сотруднику аккаунт и операционную роль. Одна роль admin не даёт
доступ к производству. Повару не требуется inventory.manage: он видит нужный справочник
и партии сырья через API производства, но не получает управление складом.

## Подготовка и рецепт

1. Кладовщик/управляющий добавляет сырьё и собственную продукцию в справочник склада.
   Для собственного готового продукта выбирают порции или штуки. Оформляет приход сырья.
2. В «Производство → Создать рецепт» выбрать готовую позицию, плановое целое количество,
   массу/объём одной готовой порции и технологию. Нормы ингредиентов относятся ко всему
   плановому выпуску. Например, норма 1 кг риса относится к 12 порциям, если плановый выход 12.
   Это пример ввода, а не норматив столовой.
3. Добавить от 1 до 30 разных ингредиентов. Сырьё можно вводить в кг/г или л/мл соответствующей
   размерности. Запятая преобразуется в точку; больше трёх дробных знаков не принимается.
4. Для изменения использовать «Новая версия» на последней версии рецепта. Старая остаётся
   доступна в истории; старые выпуски не меняются. При одновременном изменении сервер предложит
   обновить список. Создание нового рецепта для уже имеющей рецепт позиции не заменяет его.

## Выпуск

1. Открыть нужную версию и нажать «Выпустить продукцию».
2. Для каждого ингредиента выбрать конкретную партию и фактический расход. Кнопка
   «Добавить партию этого ингредиента» позволяет взять сырьё из нескольких поставок.
   Одну партию нельзя указать дважды. Недоступные партии видны, но не выбираются.
3. Указать обозначение выпуска, фактический положительный целый выход и срок пригодности
   готового продукта по правилам столовой. Даты отображаются и вводятся по Алматы.
4. Проверить пригодность сырья и подтвердить выпуск. Сервер повторно проверит свободный
   остаток и сроки. Если хоть одной партии недостаточно, ни расход, ни выпуск не сохраняются.
5. В «История выпусков» проверить фактический выход и расход. «Рецепт выпуска» открывает
   именно сохранённую версию. На складе появится отдельная готовая партия; каждое приготовление
   имеет свой UUID и время. Движения сырья и готового продукта содержат UUID выпуска.

При потере ответа повторить те же данные в открытой форме: сохранённый ключ предотвратит дубль.
После перезагрузки/закрытия формы сначала проверить историю, затем решать, нужен ли новый выпуск.
Приложение не сохраняет ключи операций и данные форм между перезагрузками.

Неверное количество исправляют отдельным складским пересчётом/списанием с причиной.
Исходный выпуск сохраняется. Приготовленное сырьё нельзя автоматически вернуть как сырое.
Стоимость готового выпуска пока не рассчитана; ноль в техническом поле не означает бесплатное
производство. Заказы, продажи, себестоимость и незавершённое производство — следующие этапы.
