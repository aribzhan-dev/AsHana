# Быстрый запуск AsHana на новом компьютере

Пошагово: от загрузки с GitHub до работающего сайта с демо-товарами. Все команды
выполняются в терминале (macOS/Linux; в Windows — Git Bash).

## 1. Что установить

- **Git** — чтобы скачать проект.
- **Docker Desktop** (или Docker Engine с Compose v2). Проверка:

  ```sh
  docker compose version
  ```

  Если Docker запущен через colima (macOS), дополнительно нужен `docker-buildx`
  (`brew install docker-buildx`), иначе сборка падает на `COPY --chmod`.
- **Python 3** — только для скрипта демо-данных и резервных копий (`python3 --version`).

Node.js и Python-библиотеки ставить не нужно: всё собирается внутри Docker.

## 2. Скачать проект

Первый раз:

```sh
git clone git@github.com:aribzhan-dev/AsHana.git
cd AsHana
```

Если SSH-ключ не настроен, используйте адрес `https://github.com/aribzhan-dev/AsHana.git`.

Если проект уже скачан — обновить его:

```sh
cd AsHana
git pull
```

## 3. Создать файл `.env`

```sh
cp .env.example .env
```

Откройте `.env` в редакторе и замените три заглушки `REPLACE…` в строках
`POSTGRES_PASSWORD`, `ASHANA_MIGRATION_PASSWORD`, `ASHANA_APP_PASSWORD` **разными**
случайными паролями. Пароль можно получить командой (выполнить три раза):

```sh
openssl rand -hex 24
```

Остальные строки можно не трогать. Telegram оставьте пустым — он выключен.
Файл `.env` не попадает на GitHub и никому не отправляется.

Пароли базы задаются один раз — при первом запуске. Если потом поменять их в `.env`,
база их не примет (см. «Частые проблемы»).

## 4. Запустить

```sh
docker compose up --build --detach --wait --wait-timeout 180
```

Первый запуск занимает несколько минут (скачиваются образы и собирается сайт).
Миграции базы выполняются автоматически. Проверка, что всё работает:

```sh
docker compose ps
```

Сервисы `db`, `api`, `web` должны быть `healthy`, `migrate` — завершён (`Exited (0)`).

Откройте сайт: **http://127.0.0.1:8080**

## 5. Создать администратора

```sh
docker compose exec api python -m ashana.bootstrap.admin
```

Команда спросит имя, логин, телефон (можно пропустить) и пароль. Пароль на экране
не отображается. Администратор создаётся только один раз.

Вход для сотрудников: **http://127.0.0.1:8080/admin** (на сайте ссылки нет специально).
Дальше администратор сам создаёт сотрудников и роли в кабинете.

## 6. Демо-товары (по желанию)

Чтобы сразу увидеть меню, склад и отчёты с данными, сохраните логин и пароль
администратора в файл `secret/admin.json` (папка не попадает на GitHub):

```json
{ "login": "ваш-логин", "password": "ваш-пароль" }
```

```sh
chmod 600 secret/admin.json
python3 -I scripts/seed_demo.py
```

Появятся поставщик, сырьё, покупные товары, блюда с рецептами и меню на 7 дней.
Повторный запуск в тот же день меню не дублирует. Подробнее — [demo-data.md](demo-data.md).

## 7. Где что находится

| Адрес | Что это |
|---|---|
| http://127.0.0.1:8080/ | Меню для гостей, заказ и тестовая оплата |
| http://127.0.0.1:8080/orders | Заказы гостя и QR-код получения |
| http://127.0.0.1:8080/admin | Кабинет сотрудников |
| http://127.0.0.1:8000/api/docs | Документация API |

Тестовая оплата принимает только карту `4242 4242 4242 4242`, любой будущий срок и CVV.
Настоящие деньги не списываются.

Сайт открывается только на этом компьютере (адрес 127.0.0.1).

## 8. Обновить после изменений на GitHub

```sh
git pull
docker compose up --build --detach --wait --wait-timeout 180
```

Данные сохраняются, новые миграции применяются сами. Перед большим обновлением
полезно сделать резервную копию (шаг 10).

## 9. Остановить

```sh
docker compose down
```

Данные остаются. Следующий запуск — та же команда из шага 4.

**Не используйте `docker compose down -v`** — эта команда удаляет базу со всеми данными.

## 10. Резервная копия

```sh
python3 -I scripts/backup_db.py backup
python3 -I scripts/backup_db.py verify backups/ashana-<дата-время>.dump
```

Копии сохраняются в `backups/` (не попадают на GitHub), хранятся 14 последних.
`verify` проверяет, что копия восстанавливается, и рабочую базу не трогает.
Восстановление и подробности — [local-development.md](local-development.md#резервная-копия-и-восстановление-pilot-01).

## Частые проблемы

- **Порт 8080 или 8000 занят.** Поменяйте `ASHANA_WEB_PORT` или `ASHANA_API_PORT` в `.env`
  (например, 8090) и повторите шаг 4. Сайт будет на новом порту.
- **`Cannot connect to the Docker daemon`.** Запустите Docker Desktop (или `colima start`).
- **Ошибка сборки про `--chmod` или BuildKit.** Установите `docker-buildx` (см. шаг 1).
- **API не становится `healthy` после смены паролей в `.env`.** База уже создана со
  старыми паролями. Верните прежние значения в `.env`. Если данные не нужны, базу можно
  пересоздать (`docker compose down -v`, затем шаг 4) — это удаляет все данные.
- **Логи сервиса:** `docker compose logs --tail 50 api` (или `web`, `db`, `migrate`).
- **«Слишком много попыток» при входе.** Защита от подбора пароля: подождите 15 минут.

Подробная инструкция для разработчиков (проверки, тесты, временные стенды) —
[local-development.md](local-development.md).
