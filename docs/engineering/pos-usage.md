# Касса POS-01 (ДЕМО)

В кабинете сотрудника откройте «Касса» (`/staff/pos`). Нужна роль кассира или управляющего
с правом pos.sell; один admin не даёт операционных прав.

1. Опубликуйте готовые блюда/покупные товары в текущем периоде меню и обеспечьте пригодный
   свободный остаток. Будущие периоды на кассе не показываются.
2. Добавьте позиции, укажите целые порции/штуки (до 100 суммарно). Корзина не резервирует.
3. «Перейти к оплате (ДЕМО)» показывает состав и сумму. Успех одновременно означает
   тестовую оплату и выдачу, без слота, предварительной комплектации и кода посетителя.
4. Отказ/таймаут сохраняет попытку, но не списывает еду; корзина остаётся для новой попытки.
   Закрытие окна до отправки ничего не записывает.
5. Успех очищает корзину. История кассы показывает сумму, время Алматы, состав и результат;
   сохраняется после обновления страницы. Это не фискальный чек и не реальная выручка.

Касса и онлайн используют одни партии. Из 5 порций при 3 онлайн-резервах касса может выдать
только 2. Истёкший неоплаченный резерв освобождается при обновлении/продаже и фоновым worker.
При изменении цены сервер отклоняет продажу; обновите меню и явно примените актуальные цены
страницы к корзине либо удалите изменённую позицию и добавьте заново. При нехватке любой
позиции вся продажа откатывается. Сырьё не списывается повторно.

При потере ответа сохранены состав и ключ операции в sessionStorage этой вкладки для
конкретного сотрудника. «Проверить результат / повторить» использует прежний ключ, включая
reload; новая продажа заблокирована до результата. Не закрывайте вкладку и не очищайте
хранилище при неизвестном результате. На другом устройстве сначала проверьте историю.
Истёкшая сессия требует входа тем же сотрудником; ключ остаётся для безопасного повтора.
Ключи с другим составом отклоняются. Повтор после отзыва роли запрещён backend.

Обновление каждые 15 секунд и кнопкой. Меню/история имеют постраничную навигацию.
Кассовые операции находятся здесь, а очередь онлайн-заказов — в «Заказы»; кассовая еда
считается выданной сразу. Telegram для кассы на этом этапе не отправляется.
Demo-продажа запрещена при environment=production. Наличные, терминал/Kaspi, возвраты,
смены кассиров и фискализация требуют отдельных задач.

## Возврат по чеку (22.10.2026)

«История продаж» → чек → **Возврат** (нужно право «Касса: возврат по чеку», есть у управляющего).
Отметьте количество по каждой позиции (не больше проданного минус прежние возвраты), выберите
«Вернуть в продажу» для целого товара или «Не возвращать в продажу» для испорченного и укажите
причину. Деньги возвращаются тем же тестовым способом оплаты; сумма видна в чеке и в отчётах
«Возвраты» и «Кассовая книга». [ADR-0019](../architecture/decisions/0019-operations-v2.md).
