# План проверок

Используются: Pytest (backend), Vitest + Testing Library (frontend), Playwright (E2E).
Конкурентные операции проверять на настоящем PostgreSQL, не на SQLite или моках репозитория.
Тестовые базы изолированы; фикстуры синтетические; тесты не соединяются с production.

| Сценарий | Ожидаемое поведение |
|---|---|
| Два клиента, последняя порция | Один заказ, второй конфликт; нет отрицательного остатка |
| Касса и online одновременно | Общий лимит не превышен |
| Две заявки на последний слот | Один успех |
| Корзина с недоступной позицией | Полный rollback, нет частичных резервов |
| Двойной checkout | Один заказ; другой payload с тем же ключом отклонён |
| Success vs expiry/cancel | Один допустимый итог; резерв/слот освобождается не более одного раза |
| Двойная выдача | Только первое завершение меняет склад |
| Производство | Сырьё списано один раз; продажа не списывает повторно |
| Отказ/таймаут mock | Нет реальной выручки, корректный retry и TTL |
| Чужой заказ/роль клиента | Доступ запрещён сервером |
| WebSocket недоступен | Заказ сохраняется, HTTP/reconnect восстанавливает экран |
| KZ телефон/имя/число | Совпадение правил UI/API, Unicode и вставка работают |
| Theme/password/responsive | Обе темы, toggle, мобильные сценарии и клавиатура |

Состояние FOUNDATION-01: Pytest — 8, Vitest — 6, Playwright/Chromium — 13 успешных тестов.
Выполнена отдельная интеграционная проверка нового PostgreSQL через
`scripts/check_foundation.py`: повторный upgrade, runtime permissions, отказ/восстановление.
IDENTITY-01: 36 backend-проверок (включая 4 PostgreSQL integration), 12 Vitest,
18 Playwright/Chromium. Покрыты CSRF/Origin, Secure/HttpOnly, ownership, TTL, logout/отзыв,
смена ролей, последний admin при гонке, rollback, постоянные лимиты, KZ-валидация,
создание сотрудника в браузере, темы, клавиатура и адаптивность.
UI-01: 48 backend (5 PostgreSQL integration), 19 Vitest, 19 Playwright/Chromium.
Проверены миграция существующего аккаунта на login, необязательный неуникальный контакт,
нормализация и уникальность login, общие поля/ошибки, dialog focus/Escape, theme icon,
кабинет администратора на 360/390/768/1280/1440 в обеих темах.
Coverage в процентах не измерялось. На момент UI-01 заказы/платежи ещё не проверялись.
Результаты и ограничения — [текущий этап](../../tasks/current-sprint.md).
После изменений запускать релевантные проверки; широкие прогоны обосновывать изменениями.
Отчёты/скриншоты/traces локальные в игнорируемых каталогах.

INVENTORY-01: 66 backend (9 PostgreSQL integration), 25 Vitest, 21 Chromium E2E.
Добавлены реальные PostgreSQL-гонки прихода/списаний, scope идемпотентности,
rollback при сбое аудита, ограничения единиц/резервов, immutable audit и проверку прав при replay.
Frontend проверяет точность денег, количество, Алматы→UTC, ошибки контракта и повтор с тем же ключом.
E2E выполняет приход→списание→пересчёт→приостановка→возобновление→история и обе темы
на 360/390/768/1280/1440. Гонки продаж/заказов не проверены: соответствующего кода ещё нет.

PRODUCTION-01: 80 backend (17 PostgreSQL integration), 29 Vitest, 23 Chromium E2E.
Проверены гонки последнего ингредиента, производство против складского списания, версий рецепта,
replay/scope, rollback при недостаче/сбое аудита, immutable history, CSRF/роли и Decimal-конверсия.
E2E проходит новую версию → фактический выпуск → историю → рецепт выпуска; обе темы/360–1440px.
Длинные native select не расширяют форму. Сценарии продаж остаются непроверенными до их реализации.

CATALOG-01: 91 backend (22 PostgreSQL integration), 36 Vitest, 24 Chromium E2E.
Проверены публикация/время, пригодный свободный готовый остаток, фильтрация до pagination,
публичный DTO без внутренних данных, version race/replay/rollback/audit/CSRF/отзыв роли.
Браузер: черновик → позиция → публикация → гостевое наличие → новая цена → снятие; обе темы
и 360–1440px. Снимок меню не доказывает корректность будущих конкурентных заказов.

ORDERS-01: checkout создаёт временное оформление, а не настоящий orders. Проверки включают
последнюю порцию/слот, checkout против складского списания, полный rollback корзины,
replay/ownership, snapshot цены, порчу резерва, cutoff 15 минут, отсутствие orders до успеха,
параллельный успех, оплату против отмены, expiry, rollback после записи outbox и повтор доставки.
E2E: корзина → оформление → отказ → успех → список сотрудника → отмена, отдельный чужой браузер,
компактный focus логина, обе темы и ширины 360/390/768/1280/1440. Количество и результаты последнего
прогона — в current-sprint.md. POS/выдача, реальный платёжный провайдер, живой Telegram,
нагрузка и Firefox/WebKit пока не проверены. Полная WCAG-аудит и coverage-проценты не измерялись.

KITCHEN-01: 109 backend (39 PostgreSQL integration), 42 Vitest, 27 Chromium E2E.
Проверены две выдачи разными сотрудниками, повтор ключа, rollback после outbox, отмена против
начала комплектации, роли/код/CSRF, непригодная партия, отсутствие повторного сырьевого расхода,
сквозная выдача и reload. Форма подтверждения проверена в обеих темах на 360–1440px.
[Актуальные результаты и ограничения](../../tasks/current-sprint.md).

POS-01: 117 backend (47 PostgreSQL integration), 46 Vitest, 28 Chromium E2E.
Покрыты общий остаток POS/online, разные кассиры/периоды, replay/rollback/FEFO,
неуспешная оплата без расхода, роли/CSRF/immutable history и raw расход только при производстве.
UI сохраняет неизвестный результат после reload/401. Обе темы/360–1440px проверены.
[Результаты и ограничения](../../tasks/current-sprint.md).

REPORTS-01: 126 backend (52 PostgreSQL integration), 49 Vitest, 29 Chromium E2E.
Событийные оплаты/выдачи/отмены, demo/real, фильтры/границы дня, точные полные итоги,
единицы/пересчёт/производство, READ ONLY/права и мобильно-тематическая матрица проверены.
Первый интеграционный прогон обнаружил двойной подсчёт отмен, итоговый исправленный прошёл.
[Актуальный этап](../../tasks/current-sprint.md).
