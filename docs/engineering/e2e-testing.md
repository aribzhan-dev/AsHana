# E2E-сценарии

Основной путь: demo login → меню → корзина → слот → mock success → кухня видит заказ →
комплектация → готов → выдача по коду → обновлённый остаток и demo-отчёт.
Другие пути: mock отказ и retry, expiry, отмена, отсутствие сети, нет остатка, заполненный слот.
Проверять наблюдаемый результат через UI и разрешённые API проверки тестовой среды.

Два browser context для разных клиентов и отдельный context сотрудника.
Не подменять конкурентный сценарий последовательными кликами одного браузера.
Использовать роли/labels, не хрупкие CSS-селекторы. Без фиксированных sleep для синхронизации.
Матрица экранов и тем описана в [frontend-foundations.md](frontend-foundations.md).
Скриншоты и traces не включать в публикацию без отдельного согласования.

## INVENTORY-01

На изолированном PostgreSQL проверить доступ manager/storekeeper, приход с переводом г→кг,
общую стоимость в тенге, списание, точный пересчёт, блокировку/возобновление партии и историю.
Проверить формы/партии на 360/390/768/1280/1440 в light/dark; снимки содержат только
синтетические данные. Гость видит вход, не остатки; секреты не записываются в traces/video.

## CATALOG-01

Manager создаёт период-черновик и позицию покупного товара, отдельный гость не видит её.
Публикация периода открывает цену/порцию/свободное количество; изменение цены и снятие
публикации отражаются после обновления гостевого меню. Сырья нет среди типов для выбора.
Гость не получает управляющий API. Проверены светлая/тёмная темы и 360–1440px;
форма позиции — 390px. Заказы/оплата остаются следующими этапами.
