# Рабочий процесс и Definition of Done

Перед изменением: прочитать AGENTS.md, требования и правила области; назвать задачу,
затронутые модули, риски, миграции и критерии приёмки. Для нового решения добавить ADR со статусом.
Маленькие изменения не требуют искусственной иерархии классов или большого плана.

Реализация → проверки → самопроверка diff → обновление требований/задач → отчёт владельцу.
Git commit/push и публикация не являются автоматическим завершением задачи.
Не запускать внешние интеграции только потому, что инструмент доступен.

## DoD для реализации

- Требование работает по позитивному и значимым негативным сценариям.
- Backend проверяет права, входные данные и бизнес-инварианты.
- Миграции воспроизводимы; секреты и данные не попали в исходники/артефакты публикации.
- Значимые unit/integration/E2E проверки выполнены; указаны точные результаты.
- Lint, форматирование и type checks выполнены после появления соответствующей конфигурации.
- Русские тексты, темы, адаптивность, password toggle и доступность проверены для затронутых экранов.
- Документация соответствует поведению. Предложения не помечены реализованными.

## DoD для текущего этапа документации

Файлы существуют, относительные ссылки корректны, навыки имеют корректный frontmatter,
ключевые требования покрыты, нет реальных секретов и автоматических Git-операций.
Проверка документов не является успешным тестом приложения.
