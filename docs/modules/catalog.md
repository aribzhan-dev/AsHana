# Меню и периоды питания

CATALOG-01 реализует R01: меню без входа, расписание периодов, цену, описание порции и
свободный готовый остаток. Оформление заказа/резервирование реализованы в ORDERS-01.
[Техническое решение](../architecture/decisions/0011-catalog-publication.md).

Управляющий (`catalog.manage`) создаёт период с названием и точным интервалом времени.
Дата списка — дата начала в Asia/Almaty. Часы завтрака/обеда не зашиты в код; длительность
положительная, не более 24 часов, допустим переход через полночь. В API время с часовым поясом,
в БД TIMESTAMPTZ, в формах/отображении Алматы. Период активен при `starts_at <= now < ends_at`.

В период добавляется собственная продукция или покупной товар из inventory_items. Название и
единица принадлежат складу; описание, порция/упаковка, цена и публикация — каталогу. Одна позиция
на товар в периоде; заменить её item_id при редактировании нельзя. Цена — BIGINT в тиынах KZT,
от 0 до 999999999999. Порция — обязательная подпись фактического размера, не коэффициент
пересчёта склада. Одна продаваемая единица соответствует одной portion/pcs склада.

Период и позиция публикуются независимо. Публичный GET `/api/v1/catalog/menu` возвращает
только опубликованные позиции опубликованных активных периодов и только при свободном остатке > 0.
Количество равно сумме `on_hand - reserved` по active-партиям того же товара, уже полученным
и ещё не просроченным на серверное время. Приостановленные партии, резервы и сырьё исключены.
Расходов, резервов и движений чтение меню не создаёт. Несколько периодов используют один остаток;
отдельного распределения по завтракам/обедам нет. Остаток — снимок, не гарантия будущего заказа.

Фильтрация выполняется до пагинации, одним SQL statement / MVCC snapshot. Публичный контракт
не содержит себестоимость, автора, идентификаторы партий и внутренних товаров, резерв или
персональные данные. Ответы no-store, серверное время — generated_at. UI обновляет меню каждые
30 секунд и при возврате в окно; ошибка убирает прежние данные. Кнопка «В корзину» начинает гостевое оформление.

Все управляющие API, включая чтение справочника и replay, проверяют сессию и catalog.manage.
CSRF обязателен для записи. Изменение + аудит before/after + запись идемпотентности фиксируются
в одной транзакции. Ключ scoped по сотруднику/операции; другой payload с тем же ключом — 409.
expected_version и row lock отклоняют устаревшую форму. При смене ролей используется общий
identity advisory lock; отозванное право не позволяет повторить сохранённую операцию.

Исправление — новая версия с before/after в append-only catalog_audit. DELETE периодов/позиций
и UPDATE/DELETE аудита запрещены runtime-роли; скрытие выполняется снятием публикации.
Снимки цены/порции в оформлениях/заказах остаются неизменными при редактировании меню.

ORDERS-01: параметр `upcoming=true` добавляет опубликованные периоды, начинающиеся в течение
24 часов, для предварительного оформления. Главная использует этот режим; без параметра API
по-прежнему показывает только текущие периоды. Остаток должен существовать сейчас; checkout
дополнительно проверяет пригодность до конца слота и закрытие приёма за 15 минут.
