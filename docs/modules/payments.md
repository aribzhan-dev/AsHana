# Тестовая оплата

В ORDERS-01 по уточнению владельца реализован минимальный mock-flow, необходимый для создания
заказа только после оплаты. Реальные реквизиты не собираются, деньги не списываются.
На каждом оформлении/заказе видна маркировка ДЕМО. HTTP mock endpoint запрещён в production.

| Событие | Результат |
|---|---|
| Успех до TTL/cutoff | Под блокировкой оформления: успешная попытка + orders + confirmed + outbox + replay в одной транзакции |
| Отказ | Append-only failed attempt; orders отсутствует, повтор до TTL возможен |
| Таймаут | Append-only timeout; успех не подтверждён, UI обновляет состояние |
| Истечение/отмена до оплаты | Нет orders; резерв и слот освобождаются один раз |
| Отмена после успеха | Заказ остаётся в истории cancelled, отдельный mock-refund и уведомление |

Сумма берётся из серверного снимка оформления, валюта KZT. payment_attempts содержит checkout_id,
mode=mock, amount_minor, outcome и время; ключ повтора scoped в order_requests. orders.payment_id
ссылается на успешную попытку, UNIQUE исключает повторное использование. Гонки успеха с отменой,
повтором и истечением сериализуются блокировкой checkout_drafts. Внешнего запроса во время транзакции нет.

Кнопка выбора исхода — исключительно симулятор, не подтверждение настоящего платежа.
Перед реальным провайдером нужны отдельный PaymentGateway, проверяемый серверный callback,
сверка сумм/валюты, внешняя идемпотентность и возвраты. Redirect клиента не доказывает оплату.
PAYMENT-01 остаётся отдельным этапом расширения/проверки платёжного контура; mock-оборот не является
реальной выручкой и не должен смешиваться с будущими денежными отчётами.

POS-01: тестовые попытки кассы хранятся отдельно в pos_attempts, только mock/KZT.
Success означает немедленную выдачу; failed/timeout не меняют остаток. Все исходы имеют
scoped replay. Реального денежного подтверждения нет. [Касса](../engineering/pos-usage.md).
