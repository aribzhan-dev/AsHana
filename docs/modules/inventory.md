# Склад и готовые остатки

INVENTORY-01 реализует справочник, партии прихода, остатки, списания, инвентаризацию
и аудит. [Инструкция](../engineering/inventory-usage.md),
[ADR-0009](../architecture/decisions/0009-inventory-ledger.md).
ORDERS-01 добавляет атомарные reserve/release и append-only аудит резервов. KITCHEN-01 добавляет однократную тестовую выдачу; POS-01 добавляет mock_pos_sale: расход только свободных готовых партий, общий с online.

Типы: сырьё (кг/г/л/мл), собственный готовый продукт (порции/шт), покупной товар (шт).
Единицы переводятся только через явный коэффициент одного измерения; килограммы не складываются с литрами.
Приход хранит количество, единицу, закупочную стоимость, дату, источник, автора и партию.
Срок годности/допустимое время реализации задаёт уполномоченный сотрудник по правилам столовой;
система не придумывает нормативы хранения еды.

Состояния партии: доступна, приостановлена, исчерпана, списана/истекла.
На сайте доступны только опубликованные позиции активного периода с пригодной партией
и свободным количеством. Сырьё на складе не делает блюдо доступным до подтверждённого выпуска.

Пример: выпущено 12, выдано 4, активный резерв 3, списаний нет → on_hand=8, available=5.
Выдача одного резерва → on_hand=7, reserved=2, available=5.
Отмена одного резерва → reserved=1, available=6, если партия всё ещё пригодна.

Списание не должно молча уничтожать обещанные резервы. При нехватке из-за порчи партия
блокируется, связанные заказы попадают на разбор сотруднику с уведомлением клиента.
Для выдачи, резерва и кассы блокировки/условные updates общие. Счётчики не уходят ниже нуля.
Инвентаризация записывает расхождение и причину, а не стирает историю движений.

Приостановка зарезервированной партии разрешена: stock_issue виден гостю и сотрудникам,
mock-оплата запрещена. Списание/пересчёт ниже reserved запрещены; отмена освобождает резерв,
но не возвращает приостановленную партию в продажу. Автоматической замены партии пока нет.
