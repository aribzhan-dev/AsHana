# Пользовательские сценарии

## Студент

Без регистрации и входа открыть меню → выбрать блюда → выбрать доступный слот → подтвердить состав и сумму →
создать временное оформление с резервом на 5 минут → пройти явно обозначенную тестовую оплату →
получить заказ и код →
следить за статусом → показать код на выдаче. Код виден владельцу гостевого секрета; он показывает его сотруднику для ввода при выдаче.
Рабочий список и Telegram код не раскрывают.
Гостевой checkout реализован в ORDERS-01, код и однократная выдача — в KITCHEN-01.

Если блюдо закончилось между просмотром и подтверждением, сервер возвращает понятную ошибку;
корзина сохраняется для изменения. Если цена изменилась, требуется повторное подтверждение суммы.
Двойной клик и повтор запроса после обрыва не создают дополнительный заказ.

## Кухня и выдача

Экран по времени выдачи; карточка содержит номер, состав, слот, состояние заказа и отдельное
состояние оплаты. После успешной mock-оплаты демонстрационный заказ поступает в очередь кухни.
Еда уже приготовлена; здесь её только порционируют и комплектуют.
Действия: начать комплектацию → готов к выдаче → выдать по коду. Повторная выдача запрещена.
При задержке сотрудник указывает проблему, клиент видит актуальный статус.
Не печатать полные телефоны и пароли на общем экране.

## Кассир

Выбрать товары → сервер проверить свободный остаток → подтвердить продажу и способ оплаты →
выдать. Касса также не работает в обход резервов. Реальная наличная оплата и mock — разные каналы.
Режим пилота и учёт реальных наличных требуют согласования до запуска с настоящими клиентами.

## Кладовщик / руководитель

Кирим сырья или готового товара → рецепт → партия производства → фактический выход →
меню по времени → продажи/резервы/списания → сверка и отчёт.
При ошибке ввода создаётся корректировка с причиной и автором, история не переписывается.

## Аккаунты сотрудников

Первый admin создаётся локально через CLI. Admin создаёт сотрудника с именем, логином, паролем и ролями; мобильный KZ-телефон
необязателен и служит контактной информацией. Admin лично выдаёт логин и пароль. Сотрудник входит через «Для сотрудников», видит свои сессии и может
их завершить. Admin находит сотрудника по логину и меняет роли; изменение завершает
его сессии. Последнего admin нельзя удалить из этой роли. Настоящих SMS и восстановления пока нет.
