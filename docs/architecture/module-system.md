# Модули и границы

| Модуль | Ответственность |
|---|---|
| identity | Пользователи, сессии, роли |
| catalog | Карточки блюд, цены, периоды меню, публикация |
| inventory | Сырьё, готовые партии, движения, резервы, свободные остатки |
| production | Версии рецептов, производственные задания, фактический выход |
| orders | Состав заказа, слоты, жизненный цикл, выдача |
| pos | Немедленная demo-продажа на кассе, неизменяемые попытки и готовый расход |
| payments | Mock attempts, результат оплаты, отмена/возврат симуляции |
| notifications | Сохранённые события и доставка уведомлений |
| reporting | Согласованные read models продаж/остатков, без изменения чужих данных |

Общий shared содержит только базовые типы денег, clock, идентификаторы и контракт UoW.
Не превращать shared в склад произвольной бизнес-логики.
Граф зависимостей контрактов должен быть ацикличным: orders оркестрирует inventory;
production оркестрирует inventory; payments подтверждает заказ через входной application contract
orders в общей транзакции, orders не импортирует payments.
UI получает состояние оплаты через отдельный запрос или явный read facade.

Внешние события не заменяют синхронную проверку остатка. Отчёты могут использовать
специализированные read queries, согласованные владельцами данных; не ORM-внутренности модулей.
