# Безопасность

Серверная валидация, object-level authorization, параметризованные запросы ORM,
CSRF для cookie-сессий, ограниченный CORS и rate limits для auth/checkout/кода выдачи.
Не хранить токены в localStorage и не вставлять пользовательский HTML через unsafe rendering.
Изображения товаров: ограничить размер/тип, безопасные имена; не загружать произвольные URL сервером.
Подробности upload определить перед реализацией, внешнее object storage не подключать автоматически.

Mock payment endpoint доступен только в явно включённой demo-среде, требует сессию и ownership;
сумма берётся из заказа, клиент не может отметить произвольный заказ оплаченным.
Реальные номера карт/CVV не принимать, не сохранять и не отправлять даже в mock: форма тестовой
оплаты принимает только опубликованные тестовые номера и не передаёт их серверу (ADR-0019).

В БД отдельный runtime user с минимальными правами; migrations выполняет отдельная роль.
Секреты через окружение/секреты Docker, не через image build args и не через frontend env.
Переменные frontend публичны после сборки. PostgreSQL не публиковать в интернет.

Логи: correlation_id и машинные коды без реквизитов, cookies, паролей и содержимого `.env`.
Резервное копирование и восстановление проверить до пилота; дампы локальные и закрытые.
Срок хранения персональных данных согласовать до реальных пользователей.
Публикации регулируются [отдельной политикой](../engineering/privacy-and-git.md).
