# Авторизация

Identity создаёт пять начальных ролей сотрудников; несколько ролей объединяют разрешения.
WORKSPACE-01: каталог ролей редактируется администратором, доступны новые роли с выбранными
правами. Таблица ниже описывает начальные значения; runtime-права берутся из БД.
Клиент остаётся гостем, отдельной роли клиента и регистрации нет (решение владельца 20.10.2026).

| Роль | Разрешения |
|---|---|
| kitchen | kitchen.read, kitchen.manage, production.manage |
| cashier | kitchen.read, orders.fulfil, pos.sell |
| storekeeper | inventory.manage |
| manager | Все перечисленные операционные права, catalog.manage, reporting.read |
| admin | Только identity.manage: создание сотрудников, поиск по логину, назначение ролей |

Admin не получает операционные права автоматически; можно назначить manager дополнительно.
Последнего активного admin нельзя лишить этой роли. Создание сотрудников и изменения ролей
сериализованы транзакционной advisory lock; проверка, запись, отзыв сессий и аудит атомарны.
Изменение на тот же набор ролей не отзывает сессии. Runtime-роль БД может создавать и изменять каталог ролей через use case,
но не удалять роли и не может переписывать audit. Аудит хранит автора, объект, действие, время и изменения ролей.

Backend проверяет identity.manage для каждого admin-действия. Сессия доступна только её
владельцу; чужой и несуществующий ID дают одинаковый 404. Body/header/localStorage не задают
доверенную роль. Скрытие UI не заменяет backend-проверку. Истёкшие и отозванные сессии дают 401.

INVENTORY-01 проверяет inventory.manage на всех маршрутах /api/v1/inventory, включая replay.
Проверка сессии и прав выполняется на той же connection; shared-lock защищает от параллельной
смены ролей до commit. PRODUCTION-01 аналогично проверяет production.manage на всех маршрутах /api/v1/production,
включая справочник, историю и replay. Кухня получает только необходимые данные сырья
через этот контракт и не получает inventory.manage. CATALOG-01 проверяет catalog.manage для периодов, позиций, справочника и replay.
Только GET /api/v1/catalog/menu публичен и возвращает ограниченный DTO без личных данных.
ORDERS-01 использует отдельный непрозрачный cookie-секрет доступа
к гостевому заказу, hash на сервере и ограничение запросов. Номер телефона и публичный
ID заказа не доказывают ownership. Код выдачи не заменяет staff-авторизацию; повторная выдача
блокируется сервером. Сотрудник видит минимум данных, необходимый для работы.

KITCHEN-01: kitchen.manage — комплектация/готовность, orders.fulfil — выдача по коду.
Права и сессия проверяются до replay в той же транзакции; общий identity lock действует до commit.
Гостю код доступен только через его cookie; рабочие ответы и Telegram его скрывают.

REPORTS-01: reporting.read проверяется для всех отчётов и справочников фильтров;
кассир/кухня/кладовщик не получают отчёты автоматически. Транзакция READ ONLY.

WORKSPACE-01: [ADR-0016](decisions/0016-workspace-role-catalog.md),
[инструкция](../engineering/workspace-usage.md). Изменение permissions отзывает сессии
носителей роли; version предотвращает потерю параллельных изменений.
