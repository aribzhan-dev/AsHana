# ADR-0017: накладная прихода и рабочие списания

Статус: принято в реализации по запросу владельца 21.10.2026.

## Контекст

Приход по одной позиции неудобен. Нужна накладная с поставщиком, складом, несколькими
товарами, ценами, расходами и полной оплатой без долга. Касса должна списывать готовые
товары с теми же гарантиями свободного остатка; история не должна мешать продаже.

## Решение

Inventory владеет inventory_directories (supplier/warehouse/payment_method),
inventory_invoices, штрихкодом товара и местом хранения партии. Invoice — append-only
снимок названий, строк и сумм. Номер уникален у поставщика. Runtime не имеет UPDATE/DELETE
накладных/справочников. Для inventory_items разрешён только UPDATE(barcode), остальные
атрибуты не получили новых прав. Смена штрихкода проверяет ожидаемое старое значение,
блокирует строку и создаёт аудит. Штрихкод необязательный и уникальный, хранится строкой.

Use case receive_invoice использует существующий UoW и scoped idempotency: авторизация,
сериализация ключа, все партии/движения, снимок накладной, audit/replay, один commit.
Любая ошибка откатывает всё. Decimal цены строки умножается на количество во входной
единице с явным HALF_UP до тиына; в партии количество переведено в базовую единицу.
Расходы — отдельная сумма накладной без произвольного распределения в себестоимость.

POS сохраняет id/name способа оплаты в неизменяемом чеке. Для старых запросов без
метода сохранены DTO-совместимость и прежний fingerprint. Настройка метода не означает
платёжную интеграцию, mode остаётся mock.

Кассовый endpoint списания использует отдельную авторизацию inventory.writeoff либо
inventory.manage, ограничивает виды товаров и операцию. Изменение использует блокировку
партии, expected_version и запрет on_hand < reserved. Повтор ключа сохраняет ровно одно движение.
Исходный складской endpoint по-прежнему требует inventory.manage. Типовые cashier/manager
получают inventory.writeoff, пользовательские роли не расширяются автоматически.

Входящие оплаченные заказы фильтруются по активным состояниям на сервере до pagination.
История сайта использует closed, касса — отдельный журнал попыток. Остатки фильтруются
по складу/названию до pagination. Места хранения принадлежат одной столовой; продажи
берут пригодные свободные партии из общего учёта. Выпуск пока относится к основному складу.

## Ограничения

Нет перемещений между складами, долгов, возврата накладной, фискализации, эквайринга,
распределения накладных расходов или удаления использованных справочников.
Непроведённая форма живёт на странице и не переживает reload; неизвестный результат
повторяется тем же ключом, а уникальность номера дополнительно защищает от дубликата.
