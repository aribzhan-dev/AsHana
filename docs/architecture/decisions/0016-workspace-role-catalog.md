# ADR-0016: рабочий кабинет и редактируемый каталог ролей

Статус: принято по запросу владельца 21.10.2026.

Ранее permissions задавались константой Python; роль можно было только назначить. Теперь
identity_roles хранит название, JSONB permissions и version. Источник прав runtime — БД.
Константы остаются только начальной спецификацией системных ролей и набором разрешённых кодов.
Новая роль не требует изменения backend-кода. Удаление ролей не добавлено: существующие
назначения и аудит сохраняются; роль можно переименовать и убрать операционные права.

IdentityService сериализует создание/редактирование через exclusive lock 71001. Операционные
UoW держат shared lock до конца транзакции, поэтому смена прав не пересекается с продажей.
version предотвращает потерю изменений двух администраторов. При смене permissions все сессии
носителей роли отзываются; при переименовании не отзываются. Все изменения аудируются.
Системная admin сохраняет identity.manage, последнего активного носителя admin нельзя лишить роли.
Runtime INSERT/UPDATE identity_roles теперь разрешены; DELETE остаётся запрещённым.

Альтернатива: отдельные permissions на каждом пользователе. Отклонена: сложнее объяснять,
поддерживать и сравнивать сотрудников одной должности. Произвольные коды прав не принимаются.

Обзор — отдельная read-only проекция reporting с одним SQL snapshot. Суммы и ранжирование
не зависят от пагинации подробного отчёта; готовые товары с нулём продаж включаются в нижний рейтинг.
Денежные значения передаются строками, на клиенте форматируются через BigInt.
Категория позиции принадлежит catalog, не меняет item_id, остаток или резерв.

Mock-режим остаётся в данных и фильтрах API; пользовательские DEMO-подписи убраны по прямому
запросу владельца. Это не включает настоящий эквайринг и не смешивает mock/real.
