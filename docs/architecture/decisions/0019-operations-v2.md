# ADR-0019: операции v2 — категории, постоянные товары, «с собой», возвраты, долги

Статус: принято по решениям владельца 22.10.2026. Миграция `0013_operations_v2`.

## Решения

- **Категории** — справочник `inventory_directories(kind='category')`. Товар и позиция меню
  выбирают категорию из списка; новая создаётся один раз для всех. Сервер приводит название
  к написанию из справочника и отклоняет неизвестное, поэтому «Вода» и «вода» не дублируются.
- **Постоянные товары** — флаг `inventory_items.always_on_menu` только для покупного товара
  с ценой продажи. Такой товар автоматически добавляется в каждый новый период и командой
  `POST /catalog/permanent/sync` в текущие и будущие периоды. Он виден, пока есть свободный
  остаток; собственная продукция исчезает с окончанием периода или порций.
  Отключение флага влияет на новые периоды; уже опубликованные позиции снимают вручную.
- **В столовой / с собой** — `checkout_drafts.dining`. Приборы и упаковка — обычные покупные
  товары категории «Приборы» со складом и ценой; гость выбирает их в корзине только для
  «с собой», и они входят в сумму и резерв как любые позиции.
- **Тестовая карта** (уточняет [ADR-0003](0003-mock-payments.md)) — форма номера, срока и CVV
  принимает только опубликованные тестовые номера (4242…, 5555…4444 — успех, 4000…0002 —
  отказ). Данные карты не покидают браузер, `autocomplete=off`; сервер получает только исход.
  Настоящие номера отклоняются в форме.
- **Возврат на кассе** — `pos_returns`, право `pos.refund` (управляющий). Частичный, не больше
  проданного за вычетом прежних возвратов; «вернуть в продажу» добавляет движение
  `pos_return` в исходную партию, «списать» оставляет склад без изменения. Идемпотентность
  и advisory lock по продаже. Возврат онлайн-заказа остаётся прежним (отмена до комплектации) — изменено в
  [ADR-0023](0023-no-refunds-no-show-password-reset.md): оплаченный заказ с сайта не отменяется.
- **Долги поставщикам** — `inventory_invoices.paid_on_receipt_minor` и append-only
  `inventory_invoice_payments`. Долг = итог − оплачено при приходе − оплаты. Оплата больше
  долга отклоняется; параллельные оплаты сериализуются advisory lock по накладной.
- **Отчёты** — добавлены ТОП, ABC, «Не продавались», «Возвраты», «Инвентаризация»,
  «Расходы и закупки», «Кассовая книга», «Долги поставщикам» и почасовая сводка.
  Все читают одним READ ONLY запросом.

## Альтернативы

Свободный текст категории с подсказками приводил к дублям. Постоянная позиция без периода
потребовала бы переписать checkout и слоты. Ввод любых номеров карт рисковал бы утечкой
настоящих реквизитов на сайт без PCI-защиты. FOR UPDATE недоступен для append-only таблиц
без права UPDATE, поэтому используются транзакционные advisory locks.

## Последствия

Банковская комиссия, рабочее время, план продаж и дивиденды не реализованы: для них нет
исходных данных. Расходы накладной в себестоимость не распределяются.
