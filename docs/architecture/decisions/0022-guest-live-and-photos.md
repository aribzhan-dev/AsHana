# ADR-0022: живая страница заказа гостя и фото блюд

Статус: принято по запросу владельца 23.10.2026. Миграции `0017_guest_live`, `0018_item_images`.
Расширяет [ADR-0020](0020-live-staff-screens.md).

## Живая страница гостя

- Триггер `order_events` добавляет в NOTIFY владельца-гостя (`checkout_drafts.guest_id`).
  Hub отправляет событие только подключению этого гостя; сам `guest_id` клиенту не уходит.
- `GET ws /api/v1/orders/live`: гостевая cookie, проверка Origin, без сессии — 4401.
  Сообщение — тема, вид и идентификатор заказа; данные страница берёт обычным HTTP.
- Страница «Мои заказы» показывает «Готовится», «Готов! Покажите QR» (с вибрацией, где
  поддерживается) и «Выдан» сразу. Без связи — опрос каждые 15 секунд.

## Фото блюд

- Фото загружает сотрудник склада к карточке готового или покупного товара
  (`PUT /api/v1/inventory/items/{id}/image`, JPEG/PNG/WebP до 8 МБ).
- Сервер всегда перекодирует фото через Pillow в WebP (длинная сторона до 800 px),
  удаляет EXIF и геометку, отклоняет изображения больше 40 мегапикселей. Хранится в БД
  (`inventory_item_images`, до 1 МБ) — попадает в резервную копию вместе с остальными данными.
- Публичный адрес — по пункту опубликованного меню: `/api/v1/media/menu/{entry_id}?v=<digest>`,
  неизменяемый кэш на год; смена фото меняет `v`. Снятый с меню пункт фото не отдаёт.
  Клиент принимает только адрес этого вида, иначе показывает рисованную заглушку.

## Альтернативы

Объектное хранилище (S3) избыточно для десятков фото; файлы на диске не попали бы в
`pg_dump`. Хранить оригинал не стали: он больше и может содержать метаданные.
