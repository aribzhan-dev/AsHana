# ADR-0023: без возврата за заказы с сайта, «Не забрали» и сброс пароля администратором

Статус: принято по решению владельца 24.10.2026. Миграция не нужна: статус `no_show` был
в схеме с ORDERS-01. Меняет правило [ADR-0019](0019-operations-v2.md) об отмене онлайн-заказа.

## Контекст

Проект показывается локально в Google Chrome; реальная оплата, Telegram (подключает владелец)
и публикация в интернет не входят в работу. Владелец задал правила:

- заказ с сайта оплачивается только на сайте (тестовой картой); наличными его не оплачивают;
- за оплаченный заказ с сайта деньги не возвращаются;
- возврат есть только на кассе и только за товар, проданный на кассе;
- если сотрудник забыл пароль, его меняет администратор.

## Решение

- Гость может отменить только **неоплаченное** оформление. Отмена оплаченного заказа
  отклоняется («деньги за заказы с сайта не возвращаются»); кнопки отмены у оплаченного
  заказа нет, перед оплатой показано предупреждение.
- **«Не забрали»** (`no_show`): оплаченный заказ в статусе «Принят», «Комплектуется» или
  «Готов», не выданный через `ASHANA_ORDER_PICKUP_GRACE_MINUTES` (по умолчанию 60) минут
  после конца выбранного слота, закрывается автоматически фоновой проверкой (раз в 15 секунд).
  Оплата остаётся (выручка, без возврата), резерв порций освобождается — еду можно продать на
  кассе или списать. Выдать такой заказ уже нельзя. Сотрудникам уходит сообщение
  «⌛ Заказ не забрали, оплата не возвращается» (в Telegram, когда он подключён).
- Возврат на кассе ищет только кассовые продажи; номер онлайн-заказа там не найден.
- **Сброс пароля:** администратор (право `identity.manage`) в карточке сотрудника задаёт
  новый пароль; все сессии сотрудника завершаются, действие пишется в журнал. Свой пароль
  через кабинет не меняют. Если администратор забыл свой пароль — команда на сервере
  `docker compose exec api python -m ashana.bootstrap.admin reset` (только локальный режим).

## Альтернативы

Возврат денег при неявке или по запросу гостя отклонён владельцем. Ручная отметка неявки
сотрудником добавила бы работу на стойке; автоматическое закрытие проще для демонстрации.
Восстановление пароля по SMS требует внешнего сервиса и не нужно для локального показа.

## Последствия

Старые записи `paid_cancelled` в отчётах сохраняются, новые не появляются. Если гость пришёл
позже срока, заказ уже «Не забрали» — решение остаётся за сотрудником (например, продать
освободившуюся порцию на кассе).
