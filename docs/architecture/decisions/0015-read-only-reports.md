# ADR-0015 — согласованные read-only отчёты

Статус: техническое решение REPORTS-01, 21.10.2026. Владелец подтвердил продолжение demo-оплаты.

reporting использует явные SQL read projections по таблицам inventory/production/orders/pos,
без импорта чужих ORM и без изменений учёта. Application открывает UoW и проверяет reporting.read
под общим identity shared lock. Транзакция READ ONLY. Параметры связаны, SQL-идентификаторы
и колонки выбираются только из констант кода.

Строки страницы, полные итоги, группировки единиц и count вычисляются одним SQL statement
из одного MVCC snapshot. Время statement_timestamp задаёт актуальность и пригодность партий.
События оплаты/выдачи/отмены фильтруются по их собственному времени, не по созданию заказа.
Неоплаченная отмена не создаёт возврат; paid_cancelled создаёт только mock-refund (с 24.10.2026
не появляется: ADR-0023).

Вместо отчёта по текущему статусу выбран журнал событий: смена статуса завтра не должна
переписать вчерашнюю оплату. Immutable снимки строк сохраняют цену продажи. Списание и
пересчёт показываются раздельно; исторический остаток не имитируется текущим on_hand.

Количества/денежные показатели возвращаются десятичными строками: PostgreSQL numeric и
крупные агрегаты не теряют точность. UI форматирует тиыны через BigInt. При разных единицах
итоги раздельные. Режим mock или real обязателен для продаж, объединения режимов нет.

На этапе нет новых таблиц/миграций, экспорта, прибыли и автоматического no-show.
Масштабные нагрузочные проверки и оптимизация индексов остаются пилотным этапом.
