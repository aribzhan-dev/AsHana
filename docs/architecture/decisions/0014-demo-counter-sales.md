# ADR-0014 — отдельная касса с общими готовыми остатками

Статус: техническое решение POS-01, 21.10.2026. Владелец разрешил demo-оплату и общий
остаток кассы/online. Детали ниже выбраны при реализации.

pos — отдельный модуль с domain/application/infrastructure/presentation. Он использует
application-порты catalog/inventory/reservations и инъецированный expire заказов. Общие
Choice/validate_choices из orders задают формат запроса; ORM чужих модулей в pos не импортируется.
Composition root связывает репозитории одной PostgreSQL-транзакцией.

Касса не создаёт искусственный гостевой аккаунт, checkout или слот. pos_attempts хранит
неизменяемые попытки (mock/KZT, success/failed/timeout, actor, JSONB-снимки цен/состава).
Только success означает немедленно выданную продажу. Неуспех не меняет склад. Это позволяет
отделять кассу от очереди комплектации и demo от будущей реальной выручки.

Порядок блокировок: права identity (shared) → actor/operation/key → отсортированные периоды →
позиции → партии UUID. Время/публикация и пригодность проверяются после ожидания блокировок.
Готовые партии расходуются FEFO только на on_hand − reserved; версия и неизменяемый
mock_pos_sale movement с ID кассовой операции пишутся вместе с попыткой, аудитом и replay.
Нехватка/сбой откатывает всё. Для нескольких карточек одного товара остаток учитывается совместно.
Сырьё, online-резервы и занятые слоты success не меняет. Expire — отдельный существующий use case.

Альтернатива: кассовый checkout в orders с фиктивным гостем/слотом. Отклонена: смешивает
немедленную выдачу с предварительной записью и расходует вместимость слотов.

Последствия: отчёты должны явно объединять online и POS и фильтровать mode/outcome.
Возвраты кассы требуют компенсирующих операций, а не редактирования истории.
Нет внешнего вызова оплаты внутри транзакции. UI сохраняет pending key/payload в sessionStorage
без auth-секретов; работает online-only. Проверка результата на другом устройстве — через историю.
