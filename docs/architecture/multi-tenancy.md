# Несколько столовых

Первая версия проектируется под одну столовую. Это ограничение явно показывается в документации.
Не реализовывать скрытую wildcard-организацию и не заявлять SaaS-изоляцию без тестов.
Филиалы и независимые владельцы — разные задачи.

При расширении потребуется ADR: границы организации, роли по столовой, tenant context
из подтверждённой сессии, уникальности в рамках организации, политика БД и тесты изоляции.
Клиентский tenant_id сам по себе не даёт доступа. Существующий проект SSS Platform
не является источником готовой tenant-модели для AsHana.
